# ChessKidoo — Website Audit & Change Log (June 2026)

A static audit across the **Admin, Student, Coach and Parent** portals, plus
the work completed this engagement. The dev sandbox couldn't boot during the
session, so verification was static (every new handler was confirmed to map to
a defined/exported function, and all script/style includes were checked).

---

## 1. What was fixed / added

### Gameplay & PGN
- **Last-move indicator** — clear amber highlight + arrow + "Opponent played …"
  banner on the play-vs-computer and multiplayer boards; teal "Last move" on the
  analysis lab board. (`board-fx.js`, wired into `engine-play.js`, `main.js`)
- **PGN Lab → My Games Vault** — local-first vault with search, filters
  (result / source / colour), win-loss-draw analytics, one-click Lichess /
  Chess.com import, and "Save to Vault". (`pgn-vault.js`)
- **Hybrid PGN backend** — `pgn_games`, `pgn_analysis`, `pgn_analysis_queue`,
  `pgn_notes` tables + a `analyze-pgn` Stockfish edge function.
  (`supabase_pgn_vault.sql`, `supabase/functions/analyze-pgn/`)

### Linked accounts
- **Unlink button** on Lichess / Chess.com / FIDE cards (clears the stored
  username so a different account can be linked). (`linked-accounts.js`, `student.js`)

### Homework (coach → student) — was broken end-to-end, now fixed
- Coach "Assign To" now lists **real students** (was hardcoded "Batch 1/2/3").
- Students now see **only homework addressed to them** (was showing everyone's).
- Grades table shows **student names** (was raw UUIDs); submissions store the name.
- **Realtime sync** of assignments + submissions via Supabase. (`classroom.js`)

### Puzzles
- Student **solved state now persists** — hydrated from `puzzle_scores` (was
  resetting to 0 every session). (`student.js`)
- Coach gains a **Student Puzzle Progress** card showing every puzzle each
  student has solved, live from the DB. (`coach.js`, `coach-panel-puzzles`)

### Student Report Card
- Wired up **View / Download PDF / Print** (the PDF export existed but no button
  called it). View opens a clean, print-ready window.
- Polished UI — restored blank icons, dynamic Term/month, competency rings.
  (`student.js`)

### Admin — Access Manager
- **Realtime auto-refresh** when the `users` table changes (new enrollments
  appear instantly; never steals focus mid-edit).
- UI polish — modern stat cards, sticky table header, row hover. (`db.js`, `redesign-2026.css`)

### Internationalisation
- **International phone** — auto-detected country-code selector (50+ countries)
  + Country field on the Book-a-Demo form; `handleDemoSubmit` builds a proper
  international number. (`i18n-enroll.js`, `main.js`)
- **Multi-currency** pricing — live rates (open.er-api.com) with a static
  fallback; converts all three plans.
- **Country-based language** — auto-selects the visitor's language from their
  locale on first visit, plus a language picker (extends the existing EN/Tamil
  `data-translate` system; the dropdown auto-grows as languages are added).

### Visual / theme
- **Redesign layer** for My Progress, Tournaments and Live Session (scoped, no
  logic changes). (`redesign-2026.css`)
- **Contrast fixes** — white-on-white in light modals/fields, unreadable native
  dropdown lists, dark-on-dark portal inputs. (`theme-contrast-fix.css`)

## 4. Added in the latest round

### GMeet automatic scheduler
- `gmeet-scheduler.js` — upcoming classes get a Meet link **automatically** (no
  manual "Generate"); links are created server-side and synced via realtime so
  students see the join link the moment a class is scheduled.
- `create-meet` edge function — **secure** Meet creation (service-account key in
  an env secret, never in the browser). The app prefers it; the legacy in-page
  path is now only a fallback.

### Mobile pass
- `mobile-optimize-2026.css` — responsive layer for the new components (PGN
  vault, report card, access manager, hero/banners, pricing controls) plus
  general fixes: wide tables scroll, 40px tap targets, 16px inputs (no iOS
  zoom), boards fit the screen, button groups wrap, safe-area padding.

### 🔐 SECURITY — action required
`gmeet-api.js` ships a Google **service-account private key** in client code.
That key is compromised by being public. **Rotate/revoke it** in Google Cloud
Console, deploy `create-meet`, then delete the `SA_CREDS` block from
`gmeet-api.js`.

## 4b. Database — fixed live via the Supabase connector ✅

Inspected the real DB and fixed it directly (no need to run the SQL files for
these — already applied):

- **9 missing tables created** (the app was silently falling back to
  localStorage for these): `student_games`, `puzzle_assignments`, `pgn_games`,
  `pgn_analysis`, `pgn_analysis_queue`, `pgn_notes`, `opening_mastery`
  (was 404-spamming every render), `tournament_interests`, `timetable_matrix`.
  Each created with the **exact column names the app sends** + the project's
  standard `ck_app_all` RLS policy + grants.
- **Realtime expanded 3 → 15 tables** (users, assignments, hw_submissions,
  puzzle_scores, puzzle_assignments, meetings, classes, multiplayer_games,
  student_games, pgn_games, pgn_analysis, opening_mastery, tournament_interests,
  timetable_matrix, broadcasts). The homework / access / puzzle / schedule
  realtime subscriptions now actually fire.
- **Advisor fixes**: pinned `search_path` on the PGN trigger function. Verified
  the auto-enqueue trigger end-to-end (insert → queued → cleaned up).
- **Known, by-design**: the "RLS policy always true" advisor warnings are the
  app's client-trust model (anon key + permissive `ck_app_all`, no Supabase
  Auth). Locking these down means migrating the whole auth model to Supabase
  Auth — a separate project, not a quick fix.
- **Still missing** (low traffic, exact shapes unconfirmed; degrade to
  localStorage): `elibrary_progress`, `video_progress`, `live_class_chats`.

## 5. Required deploy actions (remaining)
The table + realtime SQL is already applied. The repo files
`supabase_pgn_vault.sql` / `supabase_realtime_enable.sql` are kept for
version control / re-creation only.

Edge functions:
```bash
supabase functions deploy analyze-pgn --no-verify-jwt   # server-side Stockfish
supabase secrets set GOOGLE_SA_CLIENT_EMAIL="…"          # for create-meet
supabase secrets set GOOGLE_SA_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n…"
supabase functions deploy create-meet --no-verify-jwt    # secure Meet creation
```
Everything degrades gracefully to localStorage / fallback links until applied.
